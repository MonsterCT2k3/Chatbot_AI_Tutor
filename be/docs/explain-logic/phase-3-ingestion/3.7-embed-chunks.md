## 3.7 — `embed_chunks`: gọi OpenAI embeddings, batch nhiều chunk 1 request

**File:** [`app/services/ingestion_service.py`](../../../app/services/ingestion_service.py)

### Code

```python
_openai_client = AsyncOpenAI(api_key=settings.OPENAI_API_KEY)


async def embed_chunks(chunks: list[str]) -> list[list[float]]:
    if not chunks:
        return []

    async def _call():
        return await _openai_client.embeddings.create(model=settings.EMBEDDING_MODEL, input=chunks)

    response = await _retry_async(_call)
    ordered = sorted(response.data, key=lambda item: item.index)
    return [item.embedding for item in ordered]
```

### Nó làm gì (ý nghĩa)

Nhận vào danh sách các chunk text (output của 3.6), trả về danh sách vector — mỗi chunk 1 vector 1536 chiều (dimension — số lượng số thực trong 1 vector). Vector này là thứ thực sự được lưu vào `document_chunks.embedding` và dùng để tìm kiếm (similarity search) sau này ở Phase 5.

### Tại sao code theo cách này

1. **Vì sao truyền cả `chunks` (list) vào `input` cùng lúc thay vì gọi API riêng từng chunk?** — OpenAI embeddings API nhận `input` là 1 list string, trả về embedding cho tất cả trong **1 lần gọi** — đúng ý "batch" trong kế hoạch: nhanh hơn (1 round-trip mạng thay vì N lần) và rẻ hơn (ít overhead hơn) so với gọi từng chunk riêng lẻ.
2. **Vì sao sắp lại theo `item.index` (`sorted(..., key=lambda item: item.index)`) thay vì tin thẳng thứ tự `response.data`?** — Theo tài liệu OpenAI, thứ tự trả về đã khớp thứ tự input, nhưng `index` vẫn được trả kèm chính để code phía nhận có thể tự xác nhận lại — sort theo `index` là cách phòng thủ rẻ (gần như không tốn gì thêm) mà chắc chắn đúng thứ tự, không dựa vào giả định.
3. **Vì sao check `if not chunks: return []` sớm?** — Gọi API embedding với `input=[]` (danh sách rỗng) là việc thừa, có thể lỗi hoặc lãng phí 1 lần gọi mạng không cần thiết — nếu 1 trang không có chunk nào (trang trắng, xem edge case ở 3.6), nên trả về rỗng ngay, không gọi API.
4. **Tái sử dụng `_retry_async`** đã xây ở 3.2 — cùng lý do: API ngoài có thể lỗi mạng tạm thời, không nên để cả document ingest fail vì 1 lần lỗi ngẫu nhiên.

### Test đã chạy (bằng chứng thật)

- List rỗng → trả về `[]`, không gọi API.
- Embed 3 câu thật (2 câu liên quan tới "con mèo", 1 câu về "chứng khoán") trong **1 lần gọi** → nhận đúng 3 vector, mỗi vector đúng 1536 chiều (khớp với `Vector(1536)` đã định nghĩa trong `document_chunks.embedding`).
- **Sanity check ý nghĩa (không chỉ đúng shape)**: đo cosine similarity — 2 câu về "con mèo" có similarity **0.76**, câu "con mèo" với câu "chứng khoán" chỉ **0.24** — xác nhận embedding thật sự phản ánh đúng ý nghĩa ngữ semantic, không phải chỉ là số ngẫu nhiên đúng kích thước.
