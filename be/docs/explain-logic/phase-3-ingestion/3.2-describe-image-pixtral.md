## 3.2 — `_describe_image_pixtral`: mô tả 1 ảnh/diagram bằng Pixtral vision

**File:** [`app/services/ingestion_service.py`](../../../app/services/ingestion_service.py)

### Code

```python
_mistral_client = Mistral(api_key=settings.MISTRAL_API_KEY)

_IMAGE_ANALYSIS_PROMPT = (
    "Bạn là trợ lý AI chuyên phân tích tài liệu bài giảng giáo trình.\n"
    "Hãy phân tích bức ảnh này và chuyển đổi thành dạng Markdown theo cấu trúc:\n\n"
    "1. Nếu đây là **Biểu đồ, Sơ đồ kiến trúc, Quy trình, Timeline**:\n"
    "   - **Tên/Chủ đề sơ đồ**: ...\n"
    "   - **Các cột mốc / Thành phần chính**: (Mô tả chi tiết các bước, trục X/Y, các box và mũi tên)\n"
    "   - **Số liệu & Insight quan trọng**: (Liệt kê chính xác số liệu, mốc thời gian, tên công nghệ)\n"
    "   - **Ý nghĩa bài học**: (Tóm tắt 2-3 câu ngắn về bài học)\n\n"
    "2. Nếu đây là **Ảnh chụp chữ, Mã nguồn (Code) hoặc Bảng biểu**:\n"
    "   - Trích xuất 100% nội dung chữ/code ra dạng Markdown hoặc fenced code block ```python ... ```.\n\n"
    "3. Nếu đây là **Ảnh chân dung tác giả, Logo hoặc Ảnh trang trí không chứa thông tin kiến thức bài học**:\n"
    "   - Trả về ngắn gọn: `> 🖼️ *[Hình ảnh minh họa / Chân dung]*`\n\n"
    "Yêu cầu: Trả lời bằng tiếng Việt, súc tích, giữ nguyên các mốc số liệu chính xác để phục vụ cho RAG."
)


async def _retry_async(fn, max_retries: int = 5, backoff_factor: int = 2):
    for attempt in range(1, max_retries + 1):
        try:
            return await fn()
        except Exception:
            if attempt == max_retries:
                raise
            await asyncio.sleep(backoff_factor**attempt)


async def _describe_image_pixtral(image_base64: str, mime_type: str = "image/png") -> str:
    async def _call() -> str:
        response = await _mistral_client.chat.complete_async(
            model="pixtral-12b-2409",
            messages=[
                {
                    "role": "user",
                    "content": [
                        {"type": "text", "text": _IMAGE_ANALYSIS_PROMPT},
                        {"type": "image_url", "image_url": f"data:{mime_type};base64,{image_base64}"},
                    ],
                }
            ],
        )
        return response.choices[0].message.content

    return await _retry_async(_call)
```

### Nó làm gì (ý nghĩa)

Nhận vào **1 ảnh** (dạng base64 — chuỗi text biểu diễn ảnh nhị phân) và trả về **1 đoạn mô tả bằng text** cho ảnh đó. Ví dụ: đưa vào ảnh 1 sơ đồ kiến trúc, nhận về text mô tả từng bước trong sơ đồ, tên các thành phần, ý nghĩa — những thứ mà chỉ nhìn ảnh mới biết, nhưng giờ đã thành text để AI đọc được.

### Tại sao cần bước này

`extract_text_pypdf` (3.1) chỉ lấy được **chữ có sẵn trong PDF**, hoàn toàn bỏ qua nội dung nằm trong hình ảnh/diagram. Với bộ slide thật đã khảo sát, tới 85% số trang có ít nhất 1 ảnh nhúng — nếu bỏ qua, AI sẽ không "biết" nội dung của phần lớn tài liệu.

Bước này **không tự chạy một mình** — nó là 1 khối nhỏ (building block) sẽ được gọi lặp lại nhiều lần bởi `extract_text_mistral_ocr` (3.3), mỗi lần cho 1 ảnh trong 1 trang PDF. Tách riêng thành 1 hàm độc lập giúp test được ngay bây giờ (dùng ảnh có sẵn) mà không cần đợi toàn bộ pipeline OCR (3.3) code xong.

### Tại sao code theo cách này (giải thích từng quyết định)

1. **Vì sao dùng model `pixtral-12b-2409` chứ không phải để `mistral-ocr-latest` (model OCR) tự lo luôn phần ảnh?**
   `mistral-ocr-latest` chỉ trả về **vị trí ảnh** trong markdown (dạng tag `![img-0.jpeg](img-0.jpeg)`), không mô tả nội dung ảnh đó là gì. Phải dùng riêng 1 model có khả năng "nhìn hiểu" ảnh (vision model) — `pixtral-12b-2409` — để phân tích. Đây là phát hiện quan trọng từ việc đọc lại code cũ `pdf_extract/` (xem đánh giá ở [phase-3-ingestion.md](../../development-plan/phase-3-ingestion.md)).

2. **Vì sao prompt chia 3 trường hợp (biểu đồ / ảnh chữ-code / trang trí) thay vì 1 prompt chung chung "mô tả ảnh này"?**
   Nếu chỉ hỏi chung chung, model có xu hướng trả lời hời hợt hoặc dài dòng không đúng trọng tâm. Chia rõ 3 loại giúp model biết chính xác cần làm gì với từng loại ảnh: biểu đồ thì cần trích cấu trúc + số liệu; ảnh chụp code/bảng thì cần chép lại 100% nội dung chữ (không được diễn giải, vì code sai 1 ký tự là hỏng); ảnh trang trí (logo, chân dung) thì bỏ qua ngắn gọn, tránh tốn token/tiền phân tích thứ không có giá trị cho RAG. Prompt này tái sử dụng gần như nguyên bản từ code cũ vì đã kiểm chứng chất lượng tốt.

3. **Vì sao dùng `complete_async` mà không phải `complete`?**
   SDK `mistralai` có cả bản đồng bộ (`complete`, chặn luồng — blocking) và bất đồng bộ (`complete_async`). Toàn bộ hệ thống backend chạy trên `async def` (FastAPI + `asyncio`) — nếu gọi hàm blocking, nó sẽ đứng hình toàn bộ event loop trong lúc chờ Mistral trả lời (giống vấn đề đã gặp với `boto3` ở Phase 2, khi đó phải bọc bằng `run_in_threadpool`). Ở đây may mắn hơn: SDK có sẵn bản `_async` nên dùng thẳng `await`, không cần threadpool.

4. **Vì sao có `_retry_async` bọc quanh lệnh gọi API?**
   API bên ngoài (Mistral) có thể lỗi tạm thời do mạng chập chờn, SSL drop, hoặc quá tải — không phải lỗi do code sai. Nếu không retry, 1 lần lỗi mạng ngẫu nhiên sẽ làm cả document ingest thất bại (`status='failed'`) dù không có gì sai thật sự. `_retry_async` thử lại tối đa 5 lần, mỗi lần đợi lâu hơn lần trước theo cấp số nhân (`backoff_factor ** attempt` = 2, 4, 8, 16... giây) — cho hệ thống bên kia thời gian hồi phục thay vì dồn dập gọi lại ngay. Pattern này tái sử dụng ý tưởng từ code cũ (`retry_api_call`), viết lại bản async.

5. **Vì sao `mime_type` có giá trị mặc định `"image/png"` thay vì bắt buộc phải truyền vào?**
   Ảnh trích xuất từ PDF (cả ở Mistral OCR lẫn từ `page.images`) hầu như luôn là PNG. Cho giá trị mặc định giúp gọi hàm gọn hơn ở các trường hợp thông thường, nhưng vẫn cho phép truyền `mime_type` khác nếu sau này gặp định dạng khác (JPEG, WebP).

Chạy `_describe_image_pixtral` thật (tốn phí thật, ước tính dưới 1 cent) trên đúng ảnh đó — kết quả nhận diện **đúng cùng cấu trúc 5 bước**, đúng tên từng thành phần, format đúng theo prompt yêu cầu. Xác nhận hàm hoạt động đúng và chất lượng tương đương pipeline cũ đã dùng ổn định trước đây.
