## 3.12 — Test end-to-end đầy đủ, cả 3 mode

**Không có code mới** — bước cuối cùng của Phase 3, test lại toàn bộ pipeline (3.1-3.11) nhưng lần này đi **thẳng qua HTTP thật** (`signup` → `upload` → poll `/status` → verify DB), khác với các bước trước gọi `run_ingestion` trực tiếp trong script test. Đây là lần đầu tiên toàn bộ chuỗi thật sự được test đúng như cách 1 client thật (frontend) sẽ dùng.

### Mục tiêu

Xác nhận cả 4 kịch bản chính đều chạy đúng từ đầu đến cuối qua API thật, không có lỗi tích hợp nào bị bỏ sót khi các bước 3.1-3.11 (vốn test riêng lẻ) được ghép lại với nhau qua tầng HTTP.

### Kịch bản test (bằng chứng thật)

Đăng ký 1 user test thật, dùng `httpx.AsyncClient` + `ASGITransport` (đúng pattern async đã dùng xuyên suốt dự án) gọi thật `POST /api/documents` rồi poll thật `GET /{id}/status` tới khi `ready`, sau đó verify trực tiếp qua DB:

| Case | status | pages | chunks | chunks có embedding | Kiểm tra riêng |
|---|---|---|---|---|---|
| PDF thật, mode `pypdf` | `ready` | 8 | 10 | 10/10 | `metadata.extraction_mode == "pypdf"` |
| PDF thật, mode `mistral_ocr` | `ready` | 8 | 28 | 28/28 | Không còn tag `![img-...]` nào sót lại trong `raw_text` của bất kỳ trang nào — xác nhận giai đoạn 2 (mô tả ảnh, 3.2) luôn thay thế được hết tag, không bỏ sót |
| PDF thật, mode `hybrid` | `ready` | 8 | 25 | 25/25 | `metadata.extraction_mode == "hybrid"` |
| PPTX thật | `ready` | 2 | 2 | 2/2 | `converted_pdf_key` được set, tải lại được từ R2, 24097 byte, header thật `%PDF-` |

Tất cả 4 document + user test đã được xóa sạch sau khi verify xong.

### Ý nghĩa của việc test qua HTTP thay vì gọi hàm trực tiếp

Các bước 3.1-3.8 test bằng cách gọi hàm Python trực tiếp (nhanh, rẻ, dễ debug từng bước). Nhưng cách đó **không phát hiện được lỗi tích hợp ở tầng HTTP** — ví dụ: field `extraction_mode` có được parse đúng từ `multipart/form-data` không, `background_tasks` có thực sự chạy sau khi response ASGI đã trả về không, response envelope (`{success, data, error}`) có bọc đúng dữ liệu không. 3.12 test đúng những thứ đó — kết quả: không phát hiện lỗi tích hợp nào mới, toàn bộ 3.9/3.10 hoạt động đúng như đã test riêng lẻ.

### Phase 3 hoàn thành

Với 3.12 đạt yêu cầu, **Definition of Done của Phase 3 đã đạt đủ**: upload được cả PDF lẫn PPTX, chọn được 1 trong 3 `extraction_mode`, status tự chuyển `pending → parsing → embedding → ready`, đủ pages + chunks + embedding không null, PPTX có `converted_pdf_key`, mode `mistral_ocr`/`hybrid` cho ra text có mô tả ảnh thật.

**Các phát hiện phụ còn tồn đọng (không thuộc phạm vi Phase 3, ghi lại để làm sau):**
1. `document_service.delete_document` chưa xóa `converted_pdf_key` trên R2 khi xóa document PPTX — file converted bị rơi rớt lại (orphan) (ghi ở [3.8](3.8-run-ingestion.md)).
2. `_retry_async` (3.2) retry cả lỗi vĩnh viễn (401/403) giống lỗi mạng tạm thời — khiến báo lỗi cấu hình sai chậm hơn cần thiết (ghi ở [3.11](3.11-error-handling-tests.md)).

### Bước này kết nối với các bước sau như thế nào

- **3.13** (ghi chú, không phải việc code) — nút chọn `extraction_mode` trên UI là việc của frontend, backend đã sẵn sàng nhận field này từ 3.9.
- **Phase 4** (Document viewer API) sẽ dùng `document_chunks`/`document_pages` đã có dữ liệu thật từ Phase 3 để phục vụ hiển thị + trích dẫn (citation).
