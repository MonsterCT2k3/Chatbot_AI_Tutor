## 3.8 — `run_ingestion`: orchestrate toàn bộ pipeline

**File:** [`app/workers/ingestion_worker.py`](../../app/workers/ingestion_worker.py) (mới) + [`app/services/storage_service.py`](../../app/services/storage_service.py) (thêm `download_file`)

**Đặc tả trước khi code:** [`development-plan/specification-for-phase-3/3.8-run-ingestion.md`](../../development-plan/specification-for-phase-3/3.8-run-ingestion.md) — bước này phức tạp (orchestrate 7 bước đã làm + R2 + DB + status transitions) nên viết spec trước, khác với các bước đơn giản trước đó.

### Code

```python
async def download_file(key: str) -> bytes:
    response = await run_in_threadpool(_client.get_object, Bucket=settings.R2_BUCKET_NAME, Key=key)
    return await run_in_threadpool(response["Body"].read)
```

```python
async def run_ingestion(document_id: uuid.UUID) -> None:
    async with async_session() as db:
        document = await db.get(Document, document_id)
        if document is None:
            return

        try:
            document.status = "parsing"
            await db.commit()

            file_bytes = await download_file(document.storage_key)

            if document.file_type == "pptx":
                pdf_bytes = await convert_pptx_to_pdf(file_bytes)
                converted_key = f"documents/{document.user_id}/{document.id}/converted.pdf"
                await upload_file(pdf_bytes, converted_key, content_type="application/pdf")
                document.converted_pdf_key = converted_key
                await db.commit()
            else:
                pdf_bytes = file_bytes

            extraction_mode = document.metadata_.get("extraction_mode", "pypdf")

            if extraction_mode == "pypdf":
                pages = extract_text_pypdf(pdf_bytes)
            elif extraction_mode in ("mistral_ocr", "hybrid"):
                pdf_key = document.converted_pdf_key or document.storage_key
                document_url = get_presigned_url(pdf_key)
                if extraction_mode == "mistral_ocr":
                    pages = await extract_text_mistral_ocr(document_url)
                else:
                    pages = await extract_text_hybrid(pdf_bytes, document_url)
            else:
                raise ValueError(f"Unknown extraction_mode: {extraction_mode!r}")

            page_id_by_number: dict[int, uuid.UUID] = {}
            for page_number, text in pages:
                page = DocumentPage(document_id=document.id, page_number=page_number, raw_text=text)
                db.add(page)
                await db.flush()
                page_id_by_number[page_number] = page.id
            await db.commit()

            document.status = "embedding"
            await db.commit()

            chunk_rows: list[tuple[int, int, str]] = []
            for page_number, text in pages:
                for chunk_index, content in enumerate(chunk_text(text)):
                    chunk_rows.append((page_number, chunk_index, content))

            if chunk_rows:
                vectors = await embed_chunks([content for _, _, content in chunk_rows])
                for (page_number, chunk_index, content), vector in zip(chunk_rows, vectors):
                    db.add(
                        DocumentChunk(
                            document_id=document.id,
                            page_id=page_id_by_number[page_number],
                            page_number=page_number,
                            chunk_index=chunk_index,
                            content=content,
                            embedding=vector,
                        )
                    )
            await db.commit()

            document.status = "ready"
            document.page_count = len(pages)
            await db.commit()

        except Exception as e:
            await db.rollback()
            document = await db.get(Document, document_id)
            document.status = "failed"
            document.error_message = str(e)[:2000]
            await db.commit()
```

### Nó làm gì (ý nghĩa)

Là nhạc trưởng (orchestrator) của cả pipeline — nhận vào 1 `document_id` đã có sẵn record `status='pending'`, chạy tuần tự: tải file gốc từ R2 → convert PPTX nếu cần → chọn 1 trong 3 cách trích xuất text (3.1/3.3/3.4) → lưu từng trang vào `document_pages` → cắt nhỏ + tạo embedding (3.6 + 3.7) → lưu từng chunk vào `document_chunks` → đánh dấu `status='ready'`. Đây là bước biến 6 hàm rời rạc (3.1-3.7) thành 1 tính năng hoàn chỉnh, chạy được thật cho 1 document thật.

### Tại sao code theo cách này

1. **Vì sao tự mở session DB riêng (`async_session()`) thay vì nhận `db` từ tham số?** — hàm này sẽ chạy như 1 background task (chạy nền, sau khi response HTTP đã trả về, nối ở 3.9) — tại thời điểm đó session của request gốc đã đóng, bắt buộc phải tự mở session mới của riêng nó.

2. **Vì sao commit từng giai đoạn (`parsing` → pages → `embedding` → chunks → `ready`) thay vì gom hết vào 1 transaction lớn ở cuối?** — `status` phải phản ánh đúng tiến trình THẬT đã lưu trong DB tại từng thời điểm, để endpoint poll trạng thái (`GET /status`, bước 3.10 sắp làm) thấy được các bước tuần tự thật, không phải chỉ thấy `pending` rồi nhảy thẳng lên `ready`/`failed`.

3. **Vì sao `await db.flush()` ngay sau mỗi `db.add(page)` thay vì flush 1 lần ở cuối vòng lặp?** — `flush()` đẩy câu lệnh INSERT xuống DB (nhưng chưa commit — chưa lưu vĩnh viễn) và trả về `page.id` do DB tự sinh (`gen_random_uuid()`) ngay lập tức — cần có `page.id` này để gán vào `DocumentChunk.page_id` (khóa ngoại — foreign key, bắt buộc NOT NULL) ở bước sau, mà chunk lại phụ thuộc vào page nào tương ứng.

4. **Vì sao gom TOÀN BỘ chunk của cả document vào 1 list rồi mới gọi `embed_chunks` 1 LẦN, không gọi riêng cho từng trang?** — tận dụng đúng khả năng batch (gộp nhiều phần tử vào 1 lần gọi) đã xây ở 3.7 — giảm số lần gọi OpenAI API từ N (số trang) xuống còn 1, nhanh hơn và ít tốn overhead mạng hơn hẳn.

5. **Vì sao không âm thầm fallback về `pypdf` khi gặp `extraction_mode` lạ, mà raise lỗi luôn?** — 1 giá trị mode không nhận diện được (VD lỗi nhập liệu ở 3.9 sau này) nên **fail rõ ràng** (`status='failed'` + `error_message` nói đúng lý do), tốt hơn hẳn việc âm thầm dùng `pypdf` khiến người dùng tưởng mình đã chọn `mistral_ocr` nhưng thực ra không phải.

6. **Vì sao trong khối `except` phải `db.rollback()` rồi LẤY LẠI `document` bằng `db.get()` mới, không dùng lại object `document` cũ?** — sau `rollback()`, SQLAlchemy đánh dấu các object trong session là "hết hạn" (expired) — truy cập/ghi tiếp vào object cũ có thể phát sinh hành vi khó đoán. Lấy lại 1 object sạch đảm bảo việc ghi `status='failed'` luôn thành công, bất kể lỗi xảy ra ở giai đoạn nào của luồng xử lý.

7. **Vì sao thêm `download_file` mới vào `storage_service.py`?** — service này trước đó (Phase 2) chỉ cần `upload_file`/`get_presigned_url`/`delete_file` cho luồng upload/xem/xóa — chưa từng cần TẢI file gốc XUỐNG để xử lý. 3.8 là bước đầu tiên cần việc này, nên bổ sung, dùng đúng pattern `run_in_threadpool` đã có sẵn (vì `boto3` là thư viện blocking — chặn, không tự động async).

### Test đã chạy (bằng chứng thật)

Chạy trực tiếp `run_ingestion(document_id)` (chưa nối HTTP — đó là việc 3.9), dùng `b1-test.pdf` (8 trang) và 1 file `.pptx` test tạo bằng `python-pptx`, tạo document thật qua `document_service.create_document` với user thật đã có sẵn trong DB, kiểm tra bằng SQL thật qua ORM:

| Case | status | page_count | pages | chunks | ghi chú |
|---|---|---|---|---|---|
| mode `pypdf` | `ready` | 8 | 8 | 10 (đều có embedding) | text thô, có ký tự lỗi font (``) như đã biết từ trước |
| mode `mistral_ocr` | `ready` | 8 | 8 | 28 (đều có embedding) | text giàu hơn hẳn (markdown có heading, mô tả ảnh thật) |
| mode `hybrid` | `ready` | 8 | 8 | 23 (đều có embedding) | trang không ảnh giống hệt `pypdf`, trang có ảnh dùng bản OCR |
| PPTX (mode `pypdf`) | `ready` | 2 | 2 | 2 | `converted_pdf_key` được set, tải lại được từ R2, file thật bắt đầu bằng `%PDF-` |
| Lỗi (storage_key sai) | `failed` | `null` | 0 | 0 | `error_message`: `"An error occurred (NoSuchKey) when calling the GetObject operation..."`, không tạo ra page/chunk rác nào |

Tất cả 5 document test đã được xóa sạch sau khi kiểm chứng (qua `document_service.delete_document`, cascade xóa cả `document_pages`/`document_chunks`).

**Phát hiện phụ (chưa xử lý, không thuộc phạm vi 3.8):** `document_service.delete_document` hiện chỉ xóa `storage_key` trên R2, KHÔNG xóa `converted_pdf_key` — nếu xóa 1 document PPTX, file PDF đã convert sẽ bị rơi rớt lại (orphan) mãi trên R2. Không sửa ngay vì không thuộc phạm vi bước này, nhưng cần nhớ để xử lý khi quay lại `delete_document` (có thể ở 1 bước dọn dẹp sau, hoặc khi làm Phase 4/5).

### Bước này kết nối với các bước sau như thế nào

- **3.9** sẽ gọi `background_tasks.add_task(run_ingestion, document.id)` ngay sau khi `POST /api/documents` tạo xong record — không gọi trực tiếp (blocking — chặn luồng xử lý) trong request, để response trả về ngay trong khi ingest chạy nền.
- **3.10 (`GET /status`)** sẽ đọc trực tiếp `document.status`/`error_message`/`page_count` — chính là những field `run_ingestion` cập nhật ở từng giai đoạn.
