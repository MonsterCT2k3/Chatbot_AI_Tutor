## 3.3 — `extract_text_mistral_ocr`: OCR toàn bộ trang + làm giàu mô tả ảnh

**File:** [`app/services/ingestion_service.py`](../../app/services/ingestion_service.py)

### Code

```python
async def extract_text_mistral_ocr(document_url: str, pages: list[int] | None = None) -> list[tuple[int, str]]:
    async def _call():
        kwargs = {
            "model": "mistral-ocr-latest",
            "document": {"type": "document_url", "document_url": document_url},
            "include_image_base64": True,
        }
        if pages is not None:
            kwargs["pages"] = pages
        return await _mistral_client.ocr.process_async(**kwargs)

    response = await _retry_async(_call)

    results = []
    for page in response.pages:
        text = page.markdown
        for image in page.images or []:
            description = await _describe_image_pixtral(image.image_base64.split(",")[-1])
            text = text.replace(f"![{image.id}]({image.id})", description, 1)
        results.append((page.index + 1, text))
    return results
```

### Nó làm gì (ý nghĩa)

Nhận vào 1 **URL** trỏ tới file PDF (presigned URL từ R2, không phải bytes trực tiếp — khác với `extract_text_pypdf` ở 3.1), gửi cho Mistral OCR xử lý toàn bộ tài liệu (hoặc chỉ 1 số trang nếu truyền `pages`), rồi với mỗi ảnh nhúng tìm thấy trong từng trang, gọi `_describe_image_pixtral` (3.2) để lấy mô tả, và **thay thế** tag ảnh trong markdown bằng mô tả đó. Kết quả cuối cùng: `list[(page_number, text)]` giống hệt shape của 3.1, nhưng nội dung text giờ có cả phần diễn giải ảnh/diagram.

### Tại sao cần bước này

Đây là bước hiện thực hoá phát hiện quan trọng đã bàn ở phần đầu Phase 3: `mistral-ocr-latest` một mình **không đủ** — nó chỉ để lại tag placeholder (`![img-0.jpeg](img-0.jpeg)`) chỗ có ảnh, không mô tả nội dung. Hàm này ghép OCR (lấy text + vị trí ảnh) với vision (3.2, hiểu nội dung ảnh) thành 1 bước hoàn chỉnh, cho ra text thật sự "biết" cả những gì nằm trong hình.

### Tại sao code theo cách này (giải thích từng quyết định)

1. **Vì sao nhận `document_url` (URL) thay vì `pdf_bytes` như 3.1?**
   Mistral OCR API không nhận file trực tiếp qua request — nó cần 1 URL để tự tải file về xử lý phía server của Mistral. Mình tận dụng presigned URL đã có sẵn từ `storage_service.get_presigned_url()` (Phase 2) trỏ tới file trên R2, không cần upload file lên chỗ khác (khác với code cũ trong `pdf_extract/`, vốn phải upload file lên Mistral Storage riêng rồi mới lấy signed URL — 1 bước thừa mà mình không cần vì đã có R2).

2. **Vì sao có tham số `pages: list[int] | None = None`?**
   Mistral OCR API hỗ trợ chỉ xử lý 1 tập con các trang (đánh số 0-indexed) thay vì luôn luôn toàn bộ tài liệu. Để `None` mặc định nghĩa là "xử lý hết". Tham số này hiện tại 3.3 không tự dùng, nhưng bước **3.4 (`extract_text_hybrid`)** sẽ cần nó để chỉ OCR đúng những trang có ảnh — tách sẵn tham số ở đây để 3.4 tái sử dụng thẳng hàm này, không phải viết lại logic gọi API riêng.

3. **Vì sao cần `include_image_base64=True`?**
   Mặc định Mistral OCR không trả kèm dữ liệu ảnh (chỉ có text + vị trí) — nếu thiếu flag này, `page.images` sẽ rỗng và không có gì để đưa vào `_describe_image_pixtral`. Xác nhận qua test thật: có flag này, `page.images[0].image_base64` trả về đúng dữ liệu ảnh cần.

4. **Vì sao `page.index + 1` mà không phải `page.index` trực tiếp?**
   Đã kiểm chứng thật (không đoán): `page.index` của Mistral OCR đánh số **0-indexed** (trang đầu tiên trả về `index=0`). Giống lý do đã giải thích ở 3.1 — toàn hệ thống dùng số trang bắt đầu từ 1, nên phải `+1` để khớp.

5. **Vì sao thay thế bằng `text.replace(f"![{image.id}]({image.id})", description, 1)` — tại sao có tham số `1` ở cuối?**
   Đã kiểm chứng thật: Mistral trả tag ảnh dạng `![img-0.jpeg](img-0.jpeg)` — cả phần alt text và src đều là `image.id`, nên ghép đúng chuỗi đó để tìm và thay. Tham số `1` giới hạn chỉ thay **1 lần xuất hiện đầu tiên** — phòng trường hợp (hiếm) markdown có nhiều ảnh trùng `id` hoặc trùng nội dung text ở đâu đó, tránh thay nhầm hàng loạt vị trí không liên quan.

6. **Vì sao `image.image_base64.split(",")[-1]`?**
   Phòng trường hợp giá trị trả về là "data URI" đầy đủ (dạng `data:image/jpeg;base64,AAAA...`) thay vì chỉ phần base64 thuần. `.split(",")[-1]` lấy phần sau dấu phẩy cuối cùng — nếu chuỗi không có dấu phẩy (đã là base64 thuần), `split(",")` trả về list 1 phần tử và `[-1]` vẫn lấy đúng chuỗi gốc, không gây lỗi dù giá trị đến ở định dạng nào.

### Bước này kết nối với các bước sau như thế nào

- **3.4 (`extract_text_hybrid`)** sẽ gọi hàm này với `pages=[danh sách trang có ảnh]` thay vì để `None` — chỉ OCR đúng những trang cần, tiết kiệm chi phí so với OCR toàn bộ.
- **3.8 (`run_ingestion`)** sẽ gọi hàm này khi `document.metadata.extraction_mode == "mistral_ocr"`.
- Kết quả cũng lưu vào `document_pages.raw_text` giống 3.1, rồi qua `chunk_text` (3.6) như bình thường — phần code phía sau (chunk, embed) không cần biết text tới từ `pypdf` hay Mistral, vì shape trả về giống hệt nhau.
