## 4.1 — `GET /api/documents/{id}/file`

**File:** [`app/routers/documents.py`](../../app/routers/documents.py), [`app/services/document_service.py`](../../app/services/document_service.py), [`app/schemas/document.py`](../../app/schemas/document.py)

### Code

```python
# document_service.py
class DocumentNotReadyError(Exception):
    pass


def get_viewable_pdf_key(document: Document) -> str:
    # PPTX isn't renderable in a browser — PDF.js needs the LibreOffice-converted
    # copy from ingestion (Phase 3), which only exists once ingestion has run.
    if document.file_type == "pptx":
        if document.converted_pdf_key is None:
            raise DocumentNotReadyError()
        return document.converted_pdf_key
    return document.storage_key
```

```python
# schemas/document.py
class DocumentFileResponse(BaseModel):
    url: str
```

```python
# routers/documents.py
@router.get("/{document_id}/file", response_model=DocumentFileResponse)
async def get_document_file(
    document_id: uuid.UUID,
    current_user: User = Depends(get_current_user),
    db: AsyncSession = Depends(get_db),
):
    try:
        document = await get_owned_document(db, document_id, current_user.id)
        pdf_key = get_viewable_pdf_key(document)
    except DocumentNotFoundError:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail={"code": "DOCUMENT_NOT_FOUND", "message": "Document not found"},
        )
    except DocumentNotReadyError:
        raise HTTPException(
            status_code=status.HTTP_409_CONFLICT,
            detail={"code": "DOCUMENT_NOT_READY", "message": "The PDF isn't ready yet — ingestion hasn't converted it"},
        )

    return DocumentFileResponse(url=get_presigned_url(pdf_key))
```

### Nó làm gì (ý nghĩa)

Trả về 1 URL tạm thời (presigned URL — link ký sẵn, tự hết hạn sau 1 giờ, không cần thêm bước xác thực nào khác) trỏ thẳng tới file PDF thật trên R2, để frontend truyền URL đó vào PDF.js hiển thị — không phải tải file qua backend rồi backend mới trả về (tốn băng thông backend không cần thiết, R2 phục vụ trực tiếp nhanh hơn).

### Tại sao code theo cách này

1. **Vì sao logic chọn `storage_key` hay `converted_pdf_key` nằm trong `document_service.py` (`get_viewable_pdf_key`), không viết thẳng `if/else` trong router?** — đây là 1 quyết định nghiệp vụ ("file nào là bản xem được của document này"), không phải chi tiết HTTP — đặt trong service layer để tái sử dụng được sau này (VD Phase 8 citation cũng có thể cần biết PDF nào để highlight), đúng nguyên tắc router chỉ lo HTTP, service lo logic đã áp dụng xuyên suốt dự án.

2. **Vì sao có riêng `DocumentNotReadyError`, không dùng chung `DocumentNotFoundError`?** — 2 tình huống khác hẳn nhau về mặt HTTP status: document không tồn tại/không phải của user → `404` (đúng ngữ nghĩa "không có gì ở đây"); document tồn tại nhưng PPTX chưa kịp convert xong → `409 Conflict` (đúng ngữ nghĩa "có tồn tại, nhưng trạng thái hiện tại chưa cho phép làm việc này") — dùng đúng mã lỗi giúp frontend phân biệt được 2 trường hợp để xử lý khác nhau (VD 404 thì báo "không tìm thấy tài liệu", 409 thì báo "tài liệu đang được xử lý, thử lại sau").

3. **Vì sao không tự động chờ (polling) tới khi convert xong rồi mới trả URL, mà trả lỗi `409` ngay?** — endpoint HTTP nên phản hồi nhanh, không nên tự ý block (chặn) request để chờ 1 tiến trình chạy nền không rõ khi nào xong. Trách nhiệm chờ đợi nên thuộc về frontend (đã có `GET /status` từ 3.10 để poll, khi thấy `status='ready'` thì mới gọi `/file`) — tách rõ trách nhiệm: `/status` để biết KHI NÀO sẵn sàng, `/file` để LẤY file khi đã sẵn sàng.

4. **Vì sao response chỉ có đúng 1 field `url`, không kèm thêm thông tin document khác?** — endpoint có mục đích rất hẹp (chỉ để lấy URL nạp vào PDF.js), các thông tin khác của document (`filename`, `page_count`...) đã có sẵn ở `GET /{id}` — không lặp lại dữ liệu.

### Test đã chạy (bằng chứng thật)

Test qua HTTP thật (`httpx.AsyncClient` + `ASGITransport`), **tải thật presigned URL trả về** (không chỉ kiểm tra response JSON) để xác nhận URL thực sự dùng được:

| Case | Kết quả |
|---|---|
| PDF thường, đã `ready` | `200`, URL tải về đúng file PDF thật (header `%PDF-`) |
| PPTX, `converted_pdf_key` còn `null` (chưa ingest xong) | `409 DOCUMENT_NOT_READY` |
| PPTX, đã convert xong (`converted_pdf_key` có giá trị) | `200`, URL tải về đúng bản PDF đã convert (header `%PDF-`) |
| `document_id` không tồn tại | `404 DOCUMENT_NOT_FOUND` |
| Không có token xác thực | `401` |

**Lưu ý về cách test case PPTX "chưa convert xong":** không thể tái hiện qua endpoint upload thật trong môi trường test, vì `ASGITransport` (chạy app trực tiếp trong cùng process, không qua socket mạng thật) khiến `background_tasks` chạy xong TRƯỚC KHI `client.post(...)` trả về kết quả — khác với triển khai thật (`uvicorn` qua socket thật), nơi response được gửi về client trước, `background_tasks` mới chạy tiếp sau đó. Để test đúng case này, tạo thẳng 1 document PPTX qua `document_service.create_document` (không gọi `run_ingestion`) — `converted_pdf_key` chắc chắn còn `null`, test được đúng nhánh lỗi.
