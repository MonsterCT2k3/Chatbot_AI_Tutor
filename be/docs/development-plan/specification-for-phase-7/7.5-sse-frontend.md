# 7.5 — FE đọc SSE (`fetch` + status / token / replace / done)

> Spec cho **agent implement**. Backend 7.2–7.4 **đã xong**: `POST /api/sessions/{id}/messages?stream=1` trả `text/event-stream` với `status` → `token` (+ `citation`) → optional `replace` → `done` (hoặc `error`). FE hiện vẫn gọi JSON qua axios (`sendSessionMessage`) và chỉ hiện bubble assistant **sau khi** response đầy đủ.

7.5 đổi **một** đường gửi câu hỏi trên UI sang SSE. **Không** sửa backend. **Không** xóa `/ask` (7.6). Feedback URL giữ nguyên.

---

## 0. Một câu

User gửi câu → thấy `status` (tiếng Việt) → thấy nội dung assistant khi có `token` → nếu có `replace` thì **đổi** nội dung/citation → `done` gắn `answer_id` → F5 vẫn còn tin; 👍/👎 vẫn gửi được.

## 2. Quyết định đã chốt (đừng để agent chọn lại)

| # | Chốt |
|---|---|
| 1 | Transport: **`fetch`** + `response.body.getReader()` + `TextDecoder`. **Cấm** `EventSource` (chỉ GET, không gắn JWT header tùy ý như POST). |
| 2 | URL: `POST ${API_BASE_URL}/sessions/${sessionId}/messages?stream=1` với header `Accept: text/event-stream`, `Content-Type: application/json`, `Authorization: Bearer <access_token>`. Body: `JSON.stringify({ question })`. |
| 3 | `API_BASE_URL` = cùng nguồn `apiClient` (`import.meta.env.VITE_API_BASE_URL \|\| 'http://localhost:8000/api'`). Đừng hard-code lệch port. |
| 4 | `ChatPanel.sendQuestion` **chỉ** gọi hàm stream mới. Không còn `await sendSessionMessage` trên UI chính. Có thể **giữ** `sendSessionMessage` JSON trong `sessionService.js` cho debug/manual — UI không gọi. |
| 5 | Parse SSE thủ công: buffer text, tách theo `\n\n`, mỗi block lấy dòng `event:` và `data:` (JSON.parse `data`). Bỏ qua comment SSE (`:` đầu dòng) nếu có. |
| 6 | `token`: **append** `data.delta` vào `content` bubble đang stream (hiện BE gửi **một** delta full tiếng Việt — append vẫn đúng; **cấm** giả lập typewriter). |
| 7 | `citation` (từng event): **push** vào mảng `citations` của bubble đó. |
| 8 | `replace`: **gán lại** `content = data.content` và `citations = data.citations \|\| []` — **không** append. |
| 9 | `done`: gắn `answerId = data.answer_id` (và nếu muốn đồng bộ, `citations = data.citations` khi có). Kết thúc `isAsking`. |
| 10 | `status`: cập nhật text loading theo `stage` (bảng §3.3). Khi đã có `token`, **ẩn** dòng loading riêng — bubble assistant đã hiện. |
| 11 | `error` (SSE event sau khi stream đã mở): hiện `data.message` (hoặc fallback), `isAsking = false`. User bubble **giữ** (BE đã commit tin user 6.4). Bubble assistant dở: **xóa** hoặc để trống + banner lỗi — chốt: **xóa** bubble assistant streaming chưa `done`. |
| 12 | HTTP lỗi **trước** stream (401/404/409/…, `Content-Type` JSON): **không** parse SSE. Đọc body JSON; message từ `message` / `error.message` / `detail.message` như FE đang làm. |
| 13 | **401 + refresh:** axios interceptor **không** chạy trên `fetch`. Chốt: nếu `response.status === 401` **và** chưa retry: `POST /auth/refresh` với `refresh_token` (cùng shape `apiClient`), lưu token mới, **gọi lại một lần** toàn bộ `fetch` SSE. Refresh fail → xóa token + `window.location.href = '/signin'` giống `apiClient`. |
| 14 | Không đụng backend. Không yêu cầu thay event name / payload. |
| 15 | 7.6 chưa làm: feedback vẫn `POST /documents/{documentId}/ask/{answerId}/feedback`. |

## 3. Thiết kế code

### 3.1 Hợp đồng event (khớp BE 7.2–7.4 — chỉ đọc)

| event | `data` | FE làm gì |
|---|---|---|
| `status` | `{ "stage": "contextualize" \| "retrieving" \| "generating" }` | Đổi chữ loading |
| `token` | `{ "delta": string }` | Tạo bubble assistant nếu chưa có; `content += delta` |
| `citation` | `{ page_number, chunk_id, snippet }` | `citations.push(...)` |
| `replace` | `{ "content": string, "citations": [...] }` | Gán lại content + citations |
| `done` | `{ message_id, answer_id, citations }` | `answerId = answer_id`; xong |
| `error` | `{ code, message }` | Banner lỗi; dọn bubble dở |

Thứ tự điển hình grounded: `status` × N → `token` → `citation`* → `done`.  
Có judge đổi câu: … → `token` → `citation`* → `replace` → `done`.  
Input mod từ chối: `token` (refusal) → `done` (không citation / không replace).

### 3.2 `sessionService.js` — API đề xuất

```text
// Giữ:
createSession, listSessions, listMessages, deleteSession, sendSessionMessage (JSON, không dùng từ ChatPanel)

// Thêm:
export async function sendSessionMessageStream(sessionId, question, handlers)
// handlers: {
//   onStatus?(stage),
//   onToken?(delta),
//   onCitation?(citation),
//   onReplace?({ content, citations }),
//   onDone?(payload),
//   onError?(payload),   // SSE event error
// }
// throw Error / object có .message khi HTTP fail trước stream (sau khi đã thử refresh 1 lần nếu 401)
```

Bên trong:

1. `access_token = localStorage.getItem('access_token')`.
2. `fetch(url?stream=1, { method:'POST', headers:{ Authorization, Accept:'text/event-stream', Content-Type:'application/json' }, body })`.
3. Nếu 401 và `!retried` → refresh (có thể tái dùng logic giống `apiClient`, hoặc `fetch` refresh rồi retry). **Một** lần.
4. Nếu `!response.ok` → parse JSON lỗi → throw (để `ChatPanel` `errorMessage`).
5. Nếu ok nhưng không phải event-stream (phòng middleware nuốt) → throw rõ “expected SSE”.
6. Loop `reader.read()` → decode → parse blocks → gọi handler đúng `event`.
7. Kết thúc stream mà **không** có `done` và không có `error` → throw “stream ended without done” (để UI không kẹt `isAsking`).

**Không** dùng axios cho body SSE.

Refresh: nên **tái sử dụng** cùng endpoint `/auth/refresh` và localStorage keys `access_token` / `refresh_token`. Có thể extract hàm `refreshAccessToken()` dùng chung `apiClient` + stream — **không bắt buộc** nếu copy 10 dòng cẩn thận; tránh race vô hạn.

### 3.3 Map `stage` → chữ UI (cố định)

| `stage` | Text loading |
|---|---|
| `contextualize` | `Đang nối ngữ cảnh...` |
| `retrieving` | `Đang tìm trong tài liệu...` |
| `generating` | `Đang soạn câu trả lời...` |
| (unknown) | `Đang xử lý...` |

Chỗ hiện tại hard-code `"Đang tìm trong tài liệu..."` khi `isAsking` — đổi thành state `streamStatus` (string | null). Sau `token` đầu: `streamStatus = null` (bubble đã có chữ). Trước `token`: hiện bubble loading như nay (`ai-card-loading`).

### 3.4 `ChatPanel.sendQuestion` — state machine

```text
1. Guard: trim + !isAsking
2. Append user bubble; clear input; isAsking=true; streamStatus='Đang tìm trong tài liệu...' (hoặc null đến status đầu)
3. ensure session: createSession nếu chưa có (axios) — giữ skipLoadRef như hiện tại
4. let streamingIndex / flag: chưa có assistant bubble
5. await sendSessionMessageStream(sid, question, {
     onStatus(stage): set streamStatus = map(stage)
     onToken(delta):
       if chưa có bubble assistant streaming:
         append { role:'assistant', content: delta, citations:[], answerId:null, feedback:null, _streaming:true }
       else:
         cập nhật content += delta
       streamStatus = null
     onCitation(c): push vào bubble streaming
     onReplace({content, citations}): gán content + citations cho bubble streaming
     onDone(p): gán answerId = p.answer_id; nếu p.citations có thì gán citations; xóa _streaming; onSessionEnsured
     onError(p): setError(p.message); xóa bubble _streaming nếu có
   })
6. catch: setError(...); xóa bubble _streaming nếu có
7. finally: isAsking=false; streamStatus=null
```

Key React: dùng `answerId` khi có; trong lúc stream dùng key ổn định (ví dụ `streaming-pending` hoặc id tạm trong closure) — **không** remount mất chữ mỗi token.
