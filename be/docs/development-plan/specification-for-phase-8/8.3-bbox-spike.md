# 8.3 — Spike bbox vùng chữ (đo + chốt format; chưa wire production)

> Spike cho **agent implement**. 8.1–8.2 đã xong (jump trang + viền/chip). Cột `document_chunks.bbox` (JSONB) **đã có trong schema**, ingestion **chưa bao giờ ghi**. 8.3 **đo** việc lấy toạ độ chữ từ PDF eval và **chốt** format JSON + quy tắc quy đổi sang PDF.js — rồi ghi **CHOICE** có đáng wire ingest/API/FE hay không.

Giống tinh thần **7.1**: làm xong = script + mục **Kết quả đo**. **Cấm** nối chat / sửa `ask()` / đổi SSE / overlay FE production trừ khi Kết quả đo chọn wire và có bước 8.3b riêng (ngoài DoD spike này).

## 2. Bối cảnh kỹ thuật (đọc trước khi code)

1. Ingest hiện tại: text trang → `chunk_text` (~300 token) → `DocumentChunk(content, page_number, …)` **không** bbox (`ingestion_worker.py`).
2. Citation production: `citations_from_structured_answer` map **mỗi `page_number` → chunk đầu tiên trên trang đó** trong tập retrieve — không phải “đúng đoạn model vừa nói”. Spike **phải ghi** hệ quả: bbox chunk đầu trang có thể **lệch** so với câu trả lời nếu trang có nhiều chunk.
3. FE viewer: `react-pdf` / PDF.js; overlay trang 8.2 neo trên `.slide-canvas-card`. Overlay vùng (sau này) cần rect theo **viewport đang render** (width CSS của `<Page>`), không phải pixel ảnh thumbnail.
4. Hệ toạ độ PDF gốc thường **gốc dưới-trái**; PDF.js viewport sau transform thường **gốc trên-trái**. Spike phải in rõ công thức quy đổi đã dùng.
5. Dependency sẵn: `pypdfium2` (thumbnail). Có thể thử nó trước; nếu thiếu API text-box ổn → thử `pymupdf` (`fitz`) hoặc `pdfplumber` trong spike và ghi so sánh ngắn.

## 4. Việc script phải làm (đúng thứ tự)

Dùng `time.perf_counter()` khi hữu ích. Không nuốt exception — in `type(e)` + `str(e)[:500]`.

### 4.1 Lấy PDF + text trang 22

In: số trang file, độ dài text trang 22 (ký tự), 120 ký tự đầu text (một dòng).

### 4.2 Thử ít nhất một (tốt nhất hai) thư viện lấy chữ có bbox

Với mỗi lib thử được:

- Tìm các instance của `NEEDLE` (hoặc fallback: lấy **hộp bao** của toàn bộ text spans trên trang nếu search exact fail — nhưng phải ghi `MATCH=exact|page_union|fail`).
- Thu các rect thô từ lib.
- Chuẩn hoá thành candidate schema (mục 5).
- In: số rect, union box, thời gian ms.

### 4.3 Quy đổi sang “CSS pixel giả định”

Giả sử trang render với `displayWidth = 600` CSS px (như viewer có thể fit). Dùng page width/height từ PDF + công thức đã chọn → in rect CSS tương ứng (x, y, w, h).

Reviewer không cần mở UI; số phải **nhất quán** (y tăng xuống dưới sau khi lật hệ nếu gốc PDF dưới-trái).

### 4.4 (Tuỳ chọn) So với một chunk DB

Nếu script mở được DB eval: lấy 1 `DocumentChunk` `page_number=22`, in `chunk_index`, `content[:80]`, và thử match bbox cho `content[:40]` (normalize whitespace). Ghi `CHUNK_MATCH=ok|partial|fail`.

Không UPDATE row.

### 4.5 Chọn CHOICE (bắt buộc theo quy tắc)

| Điều kiện | CHOICE |
|---|---|
| Exact (hoặc near-exact) match needle trên trang 22, ≥1 rect hợp lệ, công thức CSS in được, y-direction đã lý giải | **GO_WIRE** |
| Lấy được bbox trang/union nhưng **không** match được đoạn chữ chunk/needle ổn định (dễ lệch khi wire) | **GO_AFTER_FIX** — ghi việc phải sửa (search strategy, normalize text OCR, …) |
| Lib lỗi / không có text layer / toạ độ vô nghĩa / không quy được sang PDF.js | **NO_GO** |

Không chọn **GO_WIRE** nếu chỉ có `page_union` (cả trang) — đó trùng 8.2, không chứng minh bbox đoạn.

## 5. Schema JSON đề xuất (chốt hoặc sửa có lý do trong Kết quả đo)

Lưu vào `document_chunks.bbox` (một object):

```json
{
  "version": 1,
  "coord": "pdf_user_space",
  "page_width": 612.0,
  "page_height": 792.0,
  "rects": [
    { "x": 72.0, "y": 400.0, "w": 200.0, "h": 14.0 }
  ]
}
```

| Field | Nghĩa |
|---|---|
| `version` | 1 — tăng nếu đổi semantics |
| `coord` | `pdf_user_space` = đơn vị PDF, **gốc dưới-trái** (như PDF spec). FE/8.3b đổi sang top-left khi vẽ. |
| `page_width` / `page_height` | MediaBox / crop đã dùng lúc extract |
| `rects` | Một hoặc nhiều hộp; chunk dài có thể nhiều dòng → nhiều rect. `x,y` = góc **dưới-trái** của hộp trong `pdf_user_space`. |

**Cấm** lưu tạm toạ độ đã scale theo một `displayWidth` cụ thể (gãy khi zoom).

Nếu spike chứng minh convenient hơn `coord: "pdf_top_left"` — được **đổi** nhưng phải ghi trong Kết quả đo và giữ một `coord` string rõ.

### Kết quả đo

Chạy script `be/scripts/spike_8_3_bbox.py` trên tài liệu eval `b1-full.pdf` (trang 22):

1. **Khối Output Stdout:**
```text
============================================================
OUTPUT BLOCK
============================================================
CHOICE=GO_WIRE
LIB_PRIMARY=pypdfium2
LIB_TRIED=pypdfium2,pypdf
MATCH=exact
N_RECTS=1
UNION_PDF=104.07,497.02,137.92,18.2
CSS_DISPLAY_WIDTH=600
UNION_CSS=65.04,15.49,86.2,11.38
ORIGIN_NOTE=pdf_bottom_left_to_css_top_left:css_y=(page_height-(pdf_y+pdf_h))*(display_width/page_width)
CHUNK_MATCH=ok
T_EXTRACT_MS=0.76
ERROR=none
SCHEMA_OK=true
============================================================
```

2. **Schema JSON đã chốt (lưu vào `document_chunks.bbox`):**
```json
{
  "version": 1,
  "coord": "pdf_user_space",
  "page_width": 960.0,
  "page_height": 540.0,
  "rects": [
    {
      "x": 104.07,
      "y": 497.02,
      "w": 137.92,
      "h": 18.2
    }
  ]
}
```

3. **Công thức quy đổi PDF (gốc dưới-trái) sang CSS (gốc trên-trái):**
   - `scale = displayWidth / page_width` (ví dụ `600.0 / 960.0 = 0.625`)
   - `css_x = round(pdf_x * scale, 2)` ➔ `65.04 px`
   - `css_y = round((page_height - (pdf_y + pdf_h)) * scale, 2)` ➔ `15.49 px`
   - `css_w = round(pdf_w * scale, 2)` ➔ `86.20 px`
   - `css_h = round(pdf_h * scale, 2)` ➔ `11.38 px`

4. **Đánh giá thư viện & Kết luận:**
   - `pypdfium2` đã có sẵn trong dự án, tốc độ trích xuất cực nhanh (~0.76 ms/trang), hỗ trợ tìm kiếm text chính xác và lấy bounding box từng ký tự/từ rất chuẩn. Không cần cài thêm thư viện ngoài.
   - `CHUNK_MATCH=ok`: Khớp chính xác với chunk trong database của trang 22.
   - Quyết định: **`CHOICE=GO_WIRE`**. Sẵn sàng cho bước 8.3b nếu được yêu cầu.
