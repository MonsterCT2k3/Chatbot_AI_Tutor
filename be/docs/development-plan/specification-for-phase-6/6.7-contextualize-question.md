# Đặc tả kỹ thuật — 6.7 `contextualize_question` (gộp 6.8)

> Viết **trước khi code**. Không chép implementation. Mục tiêu: đóng các lỗ mà plan gốc Phase 6 còn để hở so với code 6.4–6.6.

**Phạm vi:** 6.7 + cửa sổ lịch sử của 6.8 (một hằng số).  
**Ngoài phạm vi:** tóm tắt (summarize) lượt cũ; nối frontend; Phase 7 SSE; đổi moderation/judge.

---

## 1. Mục tiêu

Học viên hỏi nối tiếp ("phần đó là gì?", "còn bước 2?"). `similarity_search` / rerank hiện nhúng **đúng chuỗi đó** → gần như trượt chunk. Cần một câu **độc lập** để retrieve, trong khi lịch sử vẫn lưu câu **gốc**.

Đây là bước làm tốt thêm: hỏng thì retrieval dùng câu gốc, request không chết.

---

## 2. Lỗ của plan gốc so với code hiện tại

Ba chỗ plan gốc (`phase-6-chat-sessions.md` Phần 2) **không còn đúng** với 6.5:

| Plan gốc | Code 6.5 | Hệ quả nếu làm nguyên chữ |
|---|---|---|
| Nối vào `ask(session_id=...)` | Chat đi qua `send_message` → `ask_for_user` → `ask()`. Eval gọi `ask()` không có session | `ask()` phải load `chat_messages` → eval/script `/ask` cũ bị kéo theo session; ranh giới 5.6 ("`ask()` không biết user") vỡ |
| `call_group_id` sinh trong `ask()`, log contextualize cùng group | Contextualize phải chạy **trước** retrieve, tức trước thân `ask()` | Không có id để log, hoặc 2 group rời → 5.6.9 không ghép được 1 lượt hỏi |
| Lấy history rồi contextualize, không nói lúc nào so với `save_user_message` | 6.4 commit tin user **trước** LLM | Nếu load history *sau* khi save, câu vừa gửi nằm trong history → model thấy câu hiện tại **hai lần**, rewrite dễ vô nghĩa |

Spec này đóng cả ba.

## 3. Quyết định đã chốt

### 3.1 Gắn ở `send_message`, không nhét vào `ask()`

`ask()` thêm hai tham số **optional**, mặc định giữ hành vi cũ (eval, `/ask` tạm):

```text
ask(..., question, retrieve_question=None, call_group_id=None)
ask_for_user(..., question, retrieve_question=None, call_group_id=None)
```

- `question` — câu gốc (moderation đầu vào).  
- `retrieve_question` — câu dùng cho **embed + rerank + `build_prompt`**. `None` ⇒ dùng `question`.  
- `call_group_id` — nếu truyền vào thì **không** `uuid4()` thêm. `None` ⇒ `ask()` tự sinh như hiện tại.

`send_message` mới là chỗ biết session / history.

**Bỏ:** `ask(session_id=)` tự query `chat_messages`.

### 3.2 Một `call_group_id` cho cả lượt — sinh ở `send_message`

```text
call_group_id = uuid4()          # trước contextualize
contextualize_question(..., call_group_id)
ask_for_user(..., call_group_id=call_group_id)
```

Mọi dòng `ai_call_log` (contextualize, moderation, generation, judge, …) và `ai_usage_log.id` (6.6) cùng một UUID.

Eval/`/ask` không truyền id → `ask()` sinh như cũ. Không đổi hợp đồng 5.6.9 cho đường không-session.

### 3.3 Câu gốc vs câu retrieve

| Việc | Dùng câu nào |
|---|---|
| `save_user_message` / auto-title | **Gốc** |
| Input moderation trong `ask()` | **Gốc** (đúng chữ user gõ) |
| Embed, rerank, `build_prompt` | **`retrieve_question`** (độc lập) |
| Output moderation / faithfulness | Không đổi (vẫn trên câu trả lời + context) |

Generation đọc câu độc lập để khỏi trả lời đại từ mơ hồ; grounding vẫn là chunk đã retrieve.

### 3.4 Lấy history **trước** `save_user_message`

Thứ tự trong `send_message`:

```text
get_owned_session + document ready
history = N tin mới nhất của session          ← chưa có câu hiện tại
save_user_message (COMMIT T1) + touch + auto-title
nếu history rỗng → retrieve_q = question      ← không gọi LLM
nếu có history:
    check_circuit_breaker + check_daily_quota  ← tránh trả tiền rewrite khi đã 429/503
    retrieve_q = contextualize(history, question, call_group_id)
                                               ← hỏng/timeout → question gốc
ask_for_user(question=gốc, retrieve_question=retrieve_q, call_group_id)
save_assistant_message + touch
```

`ask_for_user` vẫn tự check quota/breaker lần nữa (idempotent). Check sớm chỉ để **không gọi** contextualize khi đã hết lượt.

Quota 429 sau khi đã save user: giữ hành vi 6.5 (câu hỏi còn, không có assistant).

### 3.5 Timeout, không `retry_async`

`retry_async` backoff 2+4+8+16s — không dùng. Một lần gọi, bọc `asyncio.wait_for`.

| Hằng số | Giá trị | Lý do |
|---|---|---|
| Timeout | **2.5s** | Nằm trên đường găng mọi follow-up. Judge `gpt-4o-mini` p50 ~2s là trần tham khảo; rewrite ngắn phải nhanh hơn. Chậm hơn → coi như fail. |
| Retry | **0** | Timeout xong fallback; retry biến 2.5s thành 5–10s. |
| Model | `settings.CHAT_MODEL` (`gpt-4o-mini`) | Rẻ, đủ cho rewrite. Không dùng Groq generation. |
| Output | text thuần, không structured | Một câu hỏi. Strip. Rỗng / chỉ whitespace → fallback gốc. |

Fail (timeout, API error, parse rỗng): `retrieve_q = question`, **vẫn** `log_ai_call` (latency, response ghi lý do fail). Request đi tiếp.

### 3.6 Cửa sổ lịch sử (6.8) — cắt, không tóm tắt

| Hằng số | Giá trị |
|---|---|
| `CONTEXTUALIZE_MAX_MESSAGES` | **10** (5 cặp hỏi–đáp) |

- Lấy `ORDER BY created_at DESC LIMIT 10`, đảo lại tăng dần.  
- Không cần citation.  
- Lượt user mồ côi (LLM chết sau 6.4) vẫn đưa vào — đúng chuyện đã xảy ra.  
- **Cấm summarize** trong 6.7/6.8. LLM thứ hai trên đường găng; làm sau thì spec riêng.

Câu đầu session (`history == []`): **không** gọi model.

### 3.7 Prompt (hướng, không lock wording lúc spec)

System: viết lại thành **một** câu hỏi tiếng Việt độc lập, đủ để tìm trong giáo trình khi không có hội thoại trước đó. Không trả lời, không giải thích, không markdown. Nếu đã độc lập thì trả lại nguyên văn.

User message: block lịch sử `role: content` + `Câu hiện tại: ...`.

`prompt_version` lúc log: chuỗi riêng `"contextualize-v1"`. **Không** đụng `PROMPT_VERSION` / hash `_SYSTEM_PROMPT` của generation (v8).

### 3.8 Chi phí trên `ai_usage_log`

`ask_for_user` hiện cộng token/cost **trong** `ask()` (generation + judge). Contextualize ghi `ai_call_log.estimated_cost_usd` (`estimate_cost_usd` theo `gpt-4o-mini`).

**Không** cộng vào `ai_usage_log.total_tokens` ở 6.7 — tránh sửa công thức 5.6.7. Quan sát độ trễ/hỏng = query `call_type='contextualize'`. Gộp cost lên usage log = việc riêng nếu sau này cần.

## 4. Chữ ký (hướng)

```text
contextualize_question(
    history: list[ChatMessage],   # đã cắt ≤ 10, tăng dần, chưa gồm câu hiện tại
    question: str,
    *,
    db,
    call_group_id: uuid.UUID,
) -> str
# trả về câu độc lập, hoặc question gốc nếu bỏ qua / fail
```

Luôn trả `str`, không raise tới `send_message` (trừ lỗi lập trình). Fail nằm trong hàm.

`ask(...)` / `ask_for_user(...)`: thêm `retrieve_question` và `call_group_id` như §3.1.

## 5. Luồng

```
POST /sessions/{id}/messages { question: gốc }
        │
        ├─ history = 10 tin mới nhất (trước insert)
        ├─ save_user_message(gốc)     COMMIT T1
        ├─ call_group_id = uuid4()
        │
        ├─ [history rỗng] retrieve = gốc
        └─ [có history]
              quota/breaker sớm
              contextualize ──timeout/lỗi──▶ gốc
                    │
                    └─ log_ai_call(call_type=contextualize, group=call_group_id)
        │
        ▼
ask_for_user(question=gốc, retrieve_question=retrieve, call_group_id)
        │  moderate(gốc) → embed(retrieve) → rerank(retrieve) → generate(retrieve)
        ▼
save_assistant_message(..., ai_usage_log_id=call_group_id)
```

## 7. Bất biến

1. `chat_messages` user = đúng chuỗi client gửi. Không lưu bản rewrite.  
2. Mọi `ai_call_log` của một `send_message` (kể cả contextualize) cùng `call_group_id` = `ai_usage_log.id` = `metadata.ai_usage_log_id` (6.6).  
3. `ask()` không session, không history — eval và `/ask` cũ không đổi hành vi nếu không truyền tham số mới.  
4. Timeout/lỗi contextualize ⇒ retrieve = gốc, HTTP không 5xx vì bước này.  
5. 6.4 giữ: T1 trước mọi LLM (kể cả contextualize).

## 9. Test (khi implement — chưa chạy ở bước spec)

Không golden dataset. Không cần LLM cho các case 1–4 (mock).
